# Domain playbook

## Select the method

1. To test proof construction, use a complete quantified statement and a private rubric checking hypotheses, decisive implications and edge cases. Independently verify the reference argument before using an item.
2. To test rejection of false premises, construct a witness satisfying every stated hypothesis; grade recognition, exact witness and scoped repair separately. Do not count refusal without mathematical evidence as full success.
3. To test incomplete information, remove a decisive input deliberately and specify the acceptable conditional conclusions privately. Freeze the dataset before model runs, group equivalent or parameter-renamed items into the same split, and record which tasks were exposed.

## Worked check

A toy four-item dataset has two valid claims, one false claim and one underspecified task. A system getting the two valid claims and the false-premise task right scores 3/4 overall, but 0/1 on uncertainty handling. Reporting both values prevents the aggregate from hiding that failure. This arithmetic is a dataset audit example, not an empirical result.

## Invalid inference and witness

Many generated variants do not imply many independent abilities. Ten tasks asking whether an even integer 2k is even differ syntactically but test the same immediate identity; a 10/10 score supplies no evidence about induction or limit exchange. Split by mathematical construction and reasoning obligation, not only by filename.

## Completion and handoff

Deliver public inputs and separate private rubrics, item IDs, version, provenance, capability labels and leakage audit. If an answer is unverified, mark the item provisional and exclude it from scored claims. Hand evaluation the frozen task manifest and scoring rules; report sample size and category coverage instead of extrapolating to all mathematics.
