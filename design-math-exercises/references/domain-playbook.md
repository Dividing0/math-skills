# Domain playbook: design-math-exercises

Read this when selecting a method, checking a decisive hypothesis, or reporting a completed result.

## Method branches

For a routine computational exercise, specify prerequisites, permitted tools and the exact answer domain, then solve before releasing the statement. For a proof exercise, select a theorem whose hypotheses learners can verify and grade the decisive implication rather than matching one proof template. For a counterexample exercise, require an explicit object satisfying all premises and violating the conclusion. For parameterized variants, derive admissibility inequalities symbolically and reject variants that change the intended number or type of solutions.

## Worked valid example

To teach the role of endpoints in optimization, ask students to find extrema of f(x)=x(3-x) on [0,3]. Completing the square gives f(x)=9/4-(x-3/2)². Thus the maximum is 9/4 at 3/2 and minimum is zero at both endpoints. A staged hint first asks about endpoints, then about completing the square. A rubric can award domain handling, upper bound/attainment and lower bound/attainment separately; differentiation is an equally valid alternative.

## Tempting invalid inference

Removing a point from the domain can break the task: on [0,3]\{3/2}, the same function has supremum 9/4 but no maximum. A prompt demanding its maximum would be defective unless identifying nonexistence is the learning goal.

## Stop and handoff

Deliver a verified solution, staged hints and a rubric accepting alternate arguments. If prerequisite knowledge or assessment format is missing, choose and state a modest assumption; unresolved research problems must be explicitly labelled and cannot receive a fabricated full solution.

## Application discipline

Begin by rewriting the requested conclusion with its variables, admissible inputs and exact meaning. Choose the branch whose assumptions actually hold; when several branches apply, prefer the one that produces the clearest checkable evidence. Preserve exceptional cases instead of discarding them for convenience. End with the proved result and its scope, then the specific remaining obligation if the task is only partially resolved. The worked example illustrates one branch, rather than establishing a general performance guarantee for this skill.
